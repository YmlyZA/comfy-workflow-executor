# 输出尺寸三态模式 — 设计

日期：2026-07-25
状态：已与用户对齐（三态选择器、最长边上限、表格选图即自动填均确认）

## 背景与目标

PR #6 的「锁定源图比例」是二态（关 / 锁比例填一边）。实际诉求有两种：

1. **锁定比例**：源图非常大、超出显卡能力或拖慢生成时，用户指定一边、另一边按源图比例算（现状已支持）。
2. **与源图完全一致**：输出尺寸严格等于源图（除非源图超限）——现状不支持，锁定后不填值会回落模板默认值，与用户预期不符。

本期把现有锁定 checkbox 升级为三态「输出尺寸模式」，并给「跟随源图」加可选超限保护。

已确认决策：

- 交互形态：**三态模式选择器**（模板默认 / 锁定比例 / 跟随源图），替换现有 checkbox，批量图片 tab 与表格模式统一
- 超限保护：**最长边上限**（可选，留空 = 严格跟随源图）
- 表格模式下「跟随源图」：**选图即自动填两格**（image 值变化即探测并填入宽高实际值）

## 1. 共享层（packages/shared）

### 1.1 fitSource（新纯函数 + 单测）

```
fitSource(
  source: { width: number; height: number },
  maxEdge?: number,
): { width: number; height: number }
```

- 无 `maxEdge` 或 `max(source.width, source.height) <= maxEdge` → 两维直接 `round8`
- 超限 → `scale = maxEdge / max(source.width, source.height)`，两维乘 scale 后各自 `round8`
- 复用现有 `round8(n) = max(8, round(n/8)*8)`
- 取整后最长边可能比上限多 ≤4px（如上限 1030 → 1032），接受，不做二次夹取
- source 宽或高 ≤0 抛错；`maxEdge <= 0` 视为未提供（防御，不抛错）

`computeLockedDim` 不动，「锁定比例」模式继续用它。

## 2. 前端

### 2.1 模式状态

`type SizeMode = 'default' | 'ratio' | 'source'`，默认 `'default'`。批量图片 tab 与表格模式各持一份独立状态（互不联动，与现状一致）。模板凑不齐宽高对时整个控件不渲染（沿用 PR #6 的 findDimPair 规则：第一对 type=number 且 inputName 为 width/height）。

### 2.2 批量图片 tab（ImagesEntry）

- 共享参数区：锁定 checkbox 替换为三选一（shadcn Select 或 RadioGroup，三项文案：模板默认 / 锁定比例 / 跟随源图）
- `ratio`：现状不变——「按宽定高 / 按高定宽」Select + 单个数值输入，另一维禁用显示「自动」
- `source`：出现可选「最长边上限」数字输入（placeholder「留空 = 与源图一致」，min 8）；宽高两个输入都禁用显示「自动」
- 生成任务时（沿用现有逐图 `Promise.allSettled` dims 探测）：
  - `source` 模式：每张图 `fitSource(dims, cap)` 的结果写入该任务宽高参数
  - 探测失败：该任务删除宽高键回落模板默认值 + 汇总横幅「N 张图未能获取尺寸，已用默认值」（沿用现有降级路径与文案机制）
- `default`：不探测、不写宽高（现状关闭锁定的行为）

### 2.3 表格模式（TableEntry）

- 表格上方：checkbox 替换为同款三态选择器；`source` 时旁边渲染「最长边上限」输入
- `ratio`：现状编辑驱动逻辑不变（最后编辑侧为驱动，防抖 500ms 探测后 computeLockedDim 填另一格）
- `source`：某行 image 参数值变化（上传/选择器选择/手填）→ 防抖 500ms 探测该行源图 → 成功则把该行**宽高两格都写入** `fitSource(dims, cap)` 结果；上限值变化时对已有 image 值的行同样重算
- 探测失败（404/503）→ 不自动填，沿用现有行内提示（「无法获取源图尺寸」/「ComfyUI 离线」）
- 手改语义：用户手改宽高格后手改值生效；该行 image 值再次变化（或上限变化）会重新覆盖——与 `ratio` 模式「再次编辑驱动侧会覆盖」语义一致

### 2.4 错误处理

| 场景 | 行为 |
|---|---|
| dims 404/503 | 表格：不自动填 + 行内提示；批量：该图回落模板默认值 + 汇总横幅 |
| 上限填了非法值（≤0 / 非数字） | 视为未填（严格跟随），输入框 min=8 约束 |
| 计算结果 <8 | round8 下限 8 兜底 |
| 未凑齐宽高对 | 控件不渲染 |

## 3. 服务端

**零改动**。`GET /api/comfy/image-dims` 已覆盖三来源探测（uploads 本地 → ComfyUI /view 代理），本期直接复用。

## 4. 测试策略

- **shared**：`fitSource` 单测——无上限原样 round8、恰好等于上限不缩、超限等比缩（横图/竖图/方图）、极端长宽比（8:1 全景）、上限非 8 倍数（1030 → 最长边 1032）、下限 8、maxEdge ≤0 视为未提供、source 非正抛错
- **web**：沿用无渲染测试约定；手动验收清单：
  - 批量 tab：跟随源图不填上限 → 输出与源图一致（8 取整）；填上限 → 大图缩到上限内、小图原样
  - 表格：选图即自动填两格；换图重新覆盖；改上限触发重算；手改后保留手改值
  - 三态切换：ratio ↔ source 切换后旧状态不残留（driver 值、上限值各自独立保留但互不影响生成结果）
- **server**：无新端点，无新测试

## 5. 边界（本期不做）

- 矩阵模式仍不支持
- 总像素上限不做（未来可在同一控件加规则选项）
- 多对宽高仍只作用第一对
- 不做比例预设（16:9 等）
